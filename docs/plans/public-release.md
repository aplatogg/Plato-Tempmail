# Plato-Tempmail public-release plan

Goal: publish the multi-role application with neutral branding and placeholder
deployment configuration, excluding operational data and private history.

1. Transfer the verified backend, frontend, six migrations and synthetic tests.
2. Use Plato-Tempmail branding, example domains and placeholder resource IDs.
3. Retain third-party attribution and generic deployment/security instructions.
4. Verify formatting, types, unit/tooling tests, desktop/mobile browser tests,
   local Worker integration, dry build and production dependency audit.
5. Inspect the complete intended Git tree for private data and secret patterns.
6. Publish with a GitHub noreply identity and verify the resulting remote history.
7. Keep the repository private if historical objects or auxiliary surfaces expose
   private information; do not equate a clean current tree with clean history.
